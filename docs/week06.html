予習 ── 音のしくみをすべて学ぶ ── 授業前に各自で熟読してくること

必ず予習して授業に参加すること。授業では予習で学んだことを話し合います。講師からも ランダムに口頭試問 します。回答できるように準備してください。

「音」って結局なに？ なぜ 0と1のコンピュータ で音を扱えるの？ ここでは ① 音は空気の振動 → ② アナログ信号 → ③ 標本化 → ④ 量子化 → ⑤ 正弦波の合成 → ⑥ 周波数 → ⑦ FFT の順に，図とアニメで一気に理解する。動く図は くり返し再生 される。

① 音は「空気の振動」

音の正体＝空気の疎密波

太鼓を叩くと膜が震え，まわりの 空気を押したり引いたり する。すると空気の分子が 混んでいる場所（密） と すいている場所（疎） が交互にできて，それが波になって耳まで伝わる。これが 音波（疎密波）。音を伝えているのは空気そのもので，空気が無い宇宙では音は聞こえない。

「ウェーブ（人文字）」と同じ。観客は その場で立って座るだけ なのに，波はスタジアムを ぐるっと進んで いく。空気の分子もその場で揺れるだけで，振動のパターンだけが伝わる。

② アナログ信号とは

とぎれずなめらかに変化する量

空気の密度の変化（音の強さ）を時間で測ってグラフにすると，つるんと連続したなめらかな曲線 になる。このように とぎれめなく，いくらでも細かい中間の値を取れる 信号を アナログ信号 という。マイクは空気の振動をそのまま電気の電圧の波（アナログ）に変える。

  • アナログ＝連続：音・気温・時計の長針・レコード盤の溝 など
  • デジタル＝とびとび：0と1の数字の列（コンピュータが扱える形）

③ 標本化（サンプリング）── 時間をとびとびにする

一定の時間間隔で「波の高さ」を測る

コンピュータはなめらかな曲線をそのまま覚えられない。そこで 一定の時間間隔でストップウォッチを押すように波の高さを測定 していく。これが 標本化（サンプリング）。「1秒間に何回測るか」を サンプリング周波数 という。

YouTube や CD の音は 44,100Hz ＝ 1秒間に44,100回 も測っている。回数が多いほど元のなめらかな波に近づく（＝高音質）。

④ 量子化 ── 高さもとびとびにする

測った高さを「決まった段階」に当てはめる

標本化で測った高さは中途半端な値（例：3.7段目）になる。これを あらかじめ決めた段階の，いちばん近い値に置きかえる のが 量子化。「何段階で表すか」を 量子化ビット数 という。

CD は 16bit ＝ 216 ＝ 65,536段階。段階が多いほど元の値とのズレが小さくなり，なめらかでノイズの少ない音になる。各段階に 0と1の番号（2進数） をふれば，いよいよコンピュータの数字に変わる（＝符号化）。

標本化は「時間」を，量子化は「高さ」を 方眼紙のマス目 に合わせる作業。マスを細かくする（回数・段階を増やす）ほど元の絵（音）にそっくりになる。

⑤ 正弦波の組み合わせで「あらゆる音」が作れる

いちばん単純な波＝正弦波（サイン波）

正弦波 は，円のまわりを一定の速さで回る点の高さを描いた，最もシンプルでなめらかな波（y = A sin(2πt/T)，A＝振幅＝音の大きさ，T＝周期）。1つの正弦波は「ポー」という澄んだ純音。

すごい事実： 高さ（周波数）のちがう正弦波を何本も 足し合わせる と，どんなに複雑な波形でも作れる。つまり 正弦波は音のレゴブロック。楽器の音も人の声も，正弦波の組み合わせで表せる（フーリエの考え方）。

⑥ 周波数とは何か

1秒間にくり返す波の数＝音の高さ

周波数 は「1秒間に波が何回くり返すか」で，単位は Hz（ヘルツ）。波がこまかく速くくり返す（周波数が高い）ほど 音は高く，ゆっくりだと 低く 聞こえる。

  • 440Hz ＝「ラ」（楽器のチューニングの基準）
  • 周波数を 2倍 にすると 1オクターブ上（440Hz→880Hzで1つ上のラ）
  • 人が聞こえるのは およそ 20Hz〜20,000Hz

⑦ FFTの仕組み ── 音を周波数に「バラす」

混ざった波を，正弦波の材料リストに分解する

⑤で見たように，複雑な音は正弦波の足し算でできている。逆に 「この音にはどの高さ（周波数）の正弦波がどれだけ入っているか」 を計算で求めるのが フーリエ変換。それを高速に行うアルゴリズムが FFT（高速フーリエ変換）。

FFT を通すと，時間で並んだ波（時間領域） が 周波数で並んだ棒グラフ（周波数領域＝スペクトル） に変わる。横軸＝周波数，縦軸＝その成分の大きさ（音量）。声紋分析や音楽の可視化に使われる。

FFT は プリズム。白い光（混ざった音）を通すと，赤・橙・黄…（周波数ごと）に分かれて，何色がどれだけ入っているかが見える。

まとめ：音がコンピュータに入るまで

空気の振動（①）→ なめらかな波＝アナログ（②）→ 時間をとびとびに＝標本化（③）→ 高さをとびとびに＝量子化（④）→ 0と1へ符号化 → 中身は正弦波の足し算（⑤⑥）→ FFTで周波数に分解して可視化（⑦）。

Q1. サンプリングレート 44,100Hz は何を意味するか？ レートを下げると音はどうなる？

▶ 答えを見る
「1秒間に44,100回，波の高さを測定する」という意味．レートを下げると測定回数が減り，高い周波数を表現できなくなって 音がこもる・劣化する．

Q2. 正弦波生成コードの frequency を 440 から 880 に変えると音はどう変わるか？

▶ 答えを見る
周波数が2倍になると音は 1オクターブ高く なる（ラ→1つ上のラ）．周波数が高い＝音が高い．

Q3. FFT結果で fft[:WINDOW // 2] と前半だけ使うのはなぜか？

▶ 答えを見る
FFTの結果は 左右対称 で，後半は前半の鏡像（折り返し）で新しい情報を持たない．だから 前半だけ 使えば十分．

Q4. ドミソが美しく響くのはなぜか？ ド＋ド#はなぜ濁って聞こえるか？

▶ 答えを見る
ドミソは周波数比が 4:5:6 というシンプルな整数比で，波の山がきれいに重なり協和する．ド＋ド#（半音）は比率が複雑（≈1.06）で山がずれて干渉し，濁った 不協和音 になる．

Step 1: MP3ファイルを再生する（約15分）

pydubの基本 ─ AudioSegment

ノート

pydubとは

pydub は音声ファイルをPythonで簡単に扱うためのライブラリです。MP3、WAV、OGGなど様々な形式に対応しています。音声データは AudioSegment オブジェクトとして扱います。

まず、適当なMP3ファイルを ~/MD1/no6/ に配置してください。フリー音源サイトからダウンロードしたものでOKです。

Python ── MP3再生
from pydub import AudioSegment
from pydub.playback import play

# MP3ファイルを読み込む
audio = AudioSegment.from_file("sample.mp3")

# 音声情報を表示
print(f"長さ: {len(audio)}ミリ秒")
print(f"チャンネル数: {audio.channels}")
print(f"サンプリングレート: {audio.frame_rate}Hz")
print(f"ビット深度: {audio.sample_width * 8}bit")

# 再生
play(audio)

AudioSegmentの基本操作

  • len(audio) → 長さ（ミリ秒）
  • audio[:5000] → 最初の5秒を切り出し
  • audio + audio2 → 2つの音声を連結
  • audio.apply_gain(-10) → 音量を10dB下げる
  • audio.overlay(audio2) → 2つの音声を重ねる
  • audio.export("output.wav", format="wav") → ファイルに保存

練習1: 音声を加工してみよう

ノート

読み込んだMP3を加工して再生してみましょう。

Python ── 音声加工の練習
from pydub import AudioSegment
from pydub.playback import play

audio = AudioSegment.from_file("sample.mp3")

# 最初の3秒だけ切り出す
clip = audio[:3000]

# 逆再生
reversed_clip = clip.reverse()

# 元の音 → 逆再生を連結
combined = clip + reversed_clip

ノート

音の三要素

  • 高さ（ピッチ）: 周波数（Hz）で決まる。440Hz = ラの音
  • 大きさ（音量）: 振幅で決まる。波の高さが大きいほど音が大きい

Python ── 正弦波の生成
import numpy as np
from pydub import AudioSegment
from pydub.playback import play

def create_sine_wave(frequency, duration_ms, sample_rate=44100):
    """指定した周波数・長さの正弦波を生成する"""
    num_samples = int(sample_rate * duration_ms / 1000)
    t = np.linspace(0, duration_ms / 1000, num_samples)
    wave = np.sin(2 * np.pi * frequency * t)
    wave = (wave * 32767).astype(np.int16)
    audio = AudioSegment(wave.tobytes(),
                         frame_rate=sample_rate,
                         sample_width=2,
                         channels=1)
    return audio

# ラの音（440Hz）を1秒鳴らす
la_sound = create_sine_wave(440, 1000)
play(la_sound)

Step 4: FFTで音を可視化する（約25分）

FFT（高速フーリエ変換）入門

ノート

FFTとは何か

FFT（Fast Fourier Transform / 高速フーリエ変換）は、音の波形データを周波数成分に分解する数学的手法です。

例えば、ギターの「ラ」の音は440Hzだけでなく、880Hz、1320Hz…など複数の周波数が混ざっています。FFTを使うと「この音にはどんな周波数がどれだけ含まれているか」がわかります。

虹と同じです。白い光（音の波形）をプリズム（FFT）に通すと、赤・橙・黄…と色（周波数）に分解されます。

ステップバイステップ: FFTの手順

  1. 音声データを読み込む → サンプル値の配列（波形）を得る
  2. 窓（ウィンドウ）を切り出す → 全体ではなく一部分（4096サンプルなど）を取り出す
  3. np.fft.fft() を実行 → 複素数の配列が返る
  4. np.abs() で振幅を取る → 各周波数の強さ（マグニチュード）
  5. 前半だけ使う → FFT結果は左右対称なので前半のみ有効

FFTスペクトルをpy5で描画する

ノート 
Python ── FFT可視化
import numpy as np
import py5
from pydub import AudioSegment

# 音声ファイルを読み込み、モノラルに変換
audio = AudioSegment.from_file("sample.mp3").set_channels(1)
samples = np.array(audio.get_array_of_samples())

# FFTパラメータ
WINDOW = 4096
fft = np.fft.fft(samples[:WINDOW])
magnitude = np.abs(fft[:WINDOW // 2])

def setup():
    py5.size(800, 400)
    py5.color_mode(py5.HSB, 255)
    py5.no_loop()

def draw():
    py5.background(0)

    # スペクトルを棒グラフとして描画
    for i in range(0, len(magnitude), 8):
        x = py5.remap(i, 0, len(magnitude), 0, py5.width)
        y = py5.remap(magnitude[i], 0, magnitude.max(), py5.height, 0)
        # 色を周波数に応じて変化させる（HSBカラー）
        py5.stroke(py5.remap(i, 0, len(magnitude), 0, 255), 200, 255)
        py5.line(x, py5.height, x, y)

py5.run_sketch()

コードの読み方

  • set_channels(1) → ステレオをモノラルに変換（解析を簡単にするため）
  • WINDOW = 4096 → 一度に解析するサンプル数。2のべき乗にするとFFTが高速
  • fft[:WINDOW // 2] → FFT結果の前半だけ取る（後半は対称なので不要）
  • remap() → 値の範囲を別の範囲に変換する（py5の便利関数）

Python ── ドミソ和音の生成
from pydub.generators import Sine
from pydub.playback import play

CS/DS 基礎知識

AD/DA変換（アナログ-デジタル変換）

すべてのメディアはデジタル化される

コンピュータは0と1しか扱えません。音・画像・テキストなど、あらゆる情報を数値（デジタル）に変換する必要があります。

メディアデジタル化の方法単位
音標本化（サンプリング）+ 量子化44,100 Hz / 16bit
画像ピクセル分割 + RGB値1920x1080 / 24bit
テキスト文字コード割り当てASCII / UTF-8
温度計で気温を記録するのと同じです。アナログの温度計は連続的に変化しますが、1時間ごとに値を読み取って「9時:20℃、10時:22℃…」とメモすれば、それがAD変換です。

文字コード ─ すべてはデジタル

文字も数値で表現する

  • ASCII: 英数字・記号を7bit（128文字）で表現。'A' = 65、'a' = 97、'0' = 48
  • UTF-8: 世界中の文字を可変長（1〜4バイト）で表現。日本語は3バイト/文字
  • 絵文字も数値: 「😊」は U+1F60A = 128522
Python ── 文字コードの確認
print(ord('A'))      # → 65
print(ord('あ'))     # → 12354
print(chr(65))       # → 'A'
print(chr(128522))   # → '😊'

FFT（高速フーリエ変換）

時間領域 → 周波数領域の変換

フーリエ変換は「どんな複雑な波も、単純な正弦波の組み合わせで表せる」という数学的定理に基づいています。

  • 時間領域: 横軸=時間、縦軸=振幅 → 「波形」
  • 周波数領域: 横軸=周波数、縦軸=強さ → 「スペクトル」
  • DFT（離散フーリエ変換）: デジタル信号に適用可能なフーリエ変換。計算量 O(N²)
  • FFT: DFTを高速化したアルゴリズム。計算量 O(N log N) → 実用的な速度
カクテルの味から「レモン30%、砂糖20%、ラム50%」と材料を特定するようなものです。混ざった音（カクテル）を個々の周波数（材料）に分解します。

フィルタリング概念

不要な周波数を除去する

FFTで周波数成分に分解した後、不要な成分を除去して元に戻す（逆FFT）ことで音を加工できます。

  • ローパスフィルタ: 低い周波数だけ通す → こもった音、ノイズ除去
  • ハイパスフィルタ: 高い周波数だけ通す → シャリシャリした音
  • バンドパスフィルタ: 特定の範囲だけ通す → 電話の音声（300Hz〜3400Hz）
コーヒーフィルターと同じです。豆の粒子（不要な周波数）を取り除いて、液体（欲しい周波数）だけを通します。

サンプリング定理（ナイキストの定理）

なぜサンプリングレートは44,100Hz？

ナイキストの定理: 周波数 f の音を正しくデジタル化するには、2f 以上のサンプリングレートが必要です。

  • 人間の可聴域: 約20Hz〜20,000Hz
  • 20,000Hz × 2 = 40,000Hz → 少し余裕を持って 44,100Hz
  • サンプリングレートが不足すると「エイリアシング」（偽の周波数が現れる）が発生

▶ Q1. AD変換とDA変換

音は空気の連続的な振動（アナログ）。コンピュータで扱うには数値の列（デジタル）に変換する必要がある。

AD変換: マイクで拾った連続的な波を一定間隔で測定し数値化する（アナログ→デジタル）。DA変換: デジタルデータをスピーカーで再びアナログの振動に戻して鳴らす（デジタル→アナログ）。

▶ Q2. サンプリングレート44,100Hz

「1秒間に44,100回，波の高さを測定する」という意味。レートを下げると測定回数が減り，高い周波数が表現できなくなって 音がこもる・劣化する。

▶ Q3. 音の三要素

高さ（ピッチ）＝周波数（Hz），大きさ（音量）＝振幅（波の高さ），音色（ティンバー）＝波の形。

▶ Q4. frequency を 440→880

周波数が2倍になると音は 1オクターブ高く なる（ラ→1つ上のラ）。周波数が高いほど音が高い。

▶ Q5. 振幅と純音

振幅を大きくすると 音量が大きく なる（音の高さは変わらない）。「正弦波＝純音」は，1つの周波数だけからなる最も単純な波で，倍音を含まない澄んだ音という意味。

▶ Q6. FFTとは

波形データを 周波数成分に分解 する手法。時間で並んだデータ（時間領域）を周波数で並んだデータ（周波数領域）に変換し，「どの周波数がどれだけ含まれているか」が分かる。

▶ Q7. 前半だけ使う理由

FFTの結果は 左右対称。後半は前半の鏡像（折り返し）で新しい情報を持たないため，[:WINDOW // 2] で前半だけ使えば十分。

▶ Q8. 窓を2のべき乗にする理由

FFTのアルゴリズムは窓のサイズが 2のべき乗（…，2048，4096，…）のとき最も効率よく 高速に計算 できるため。だから 4096 などを使う。

▶ Q9. ドミソが協和する理由

ミ/ド ≈ 5/4，ソ/ド ≈ 3/2 と シンプルな整数比（ドミソ＝4:5:6）になり，波の山が規則的に重なるため協和して美しく聞こえる。

▶ Q10. ド＋ド#が濁る理由

ド#/ド ≈ 1.06 という 複雑な比率 で，波の山がきれいに重ならず干渉してうなりが生じる。協和音（単純な整数比）と違い，濁った 不協和音 になる。
