DOM操作の4つの命令 ─ 機能と使い方（早見表）

JavaScriptで図形を出すときに毎回使う4つ。「場所を探す → 作る → 設定する → 入れる」の順で使う。この表は今日ずっと手元に置いておくとよい。

命令何をするか（機能）書き方（使い方）具体例
querySelector すでにある要素を1つ探して取ってくる（新しくは作らない） 親.querySelector('セレクタ') document.querySelector('#group')
→ id="group" の要素を取得
createElement 新しい要素（タグ）を1つ作る。この時点ではまだ画面に出ない document.createElement('タグ名') document.createElement('a-sphere')
→ 中身が空の a-sphere が1つできる
setAttribute 要素に属性（設定）を与える／書きかえる（位置・色・大きさなど） 要素.setAttribute('属性名', 値) ball.setAttribute('color', 'gold')
→ その球を金色にする
appendChild 作った要素を親の中に入れる。ここで初めて画面に出る 親.appendChild(要素) group.appendChild(ball)
→ #group の中に球が追加され表示される
  • セレクタの書き方（querySelector に渡す文字）：'#group'＝id、'.box'＝class、'a-sphere'＝タグ名。CSSと同じ書き方
  • createElement と appendChild はセット。createElement で作っただけでは見えず、appendChild で入れて初めて表示される（「作る」と「置く」は別の作業）
  • 使う順番：querySelector で入れ物を得る → createElement で作る → setAttribute で設定 → appendChild で入れる
料理でたとえると：querySelector＝盛りつける皿を用意する／createElement＝料理を1品作る／setAttribute＝味つけ・盛りつけ／appendChild＝皿にのせて食卓に出す。
HTMLの書き方：「デザイン」と「ロジック」を分け、<script> を書く場所にこだわる

A-FrameのHTMLは、大きく2つの部分に分けて考えると迷わない。

① デザイン（見た目・構造）
<a-scene> の中のタグ（a-sky・a-plane・a-entity）。「何を置くか」を書く
② ロジック（処理）
<script> の中のJavaScript。「どう作るか・動かすか」を書く

<script> は </a-scene> の後、</body> の直前に書く

HTML
<body>
  <!-- ① デザイン：何を置くか（先に書く） -->
  <a-scene>
    <a-sky ...></a-sky>
    <a-entity id="group"></a-entity>
  </a-scene>

  <!-- ② ロジック：どう作る・動かすか（デザインの後に書く） -->
  <script>
    const group = document.querySelector('#group');  // ← 上の #group を探す
    // ... 図形を作る処理 ...
  </script>
</body>

なぜ「デザイン → ロジック」の順なのか

  • ブラウザはHTMLを上から順に読む。<script> を先に書くと、まだ <a-entity id="group"> が作られていない
  • その状態で document.querySelector('#group') を呼ぶと見つからず（null）エラーになる
  • だからデザイン（要素）を先に置き、ロジック（script）を後に置く。「材料をそろえてから料理する」イメージ

「<script> は <body> の外に書けばいいのでは？」という疑問

  • <script> を正しく置ける場所は <head> の中か <body> の中のどちらかだけ。</body> や </html> より後ろに書くのはHTMLの仕様上は不正
  • ただし多くのブラウザはエラー回復処理を行うので、</body> の後ろに書いても実際には実行されることが多い。ここは「body 内に移動して DOM が書きかわる」のではなく、パーサがそう解釈してくれるだけ、というのが正確（動的にHTMLを読み込む場合や XML/XHTML として解析される場合は、期待どおり動かないこともある）
  • まとめると、実際には動くことが多いが、仕様上は書くべきではない。<body> の外に出すメリットは無いので、素直に body 内に置けばよい
  • <head> に置くと、まだ図形の要素が作られていないうちに実行され、querySelector('#group') が null になってエラー。だから head でもダメ
  • 結論：要素の後ろ＝</a-scene> の後、</body> の直前に置くのが、いちばん確実でシンプル。第1回・第2回の資料もすべてこの形
  • （発展）どうしても <head> に置きたいときは、外部ファイルに <script defer src="..."> を付けるか、DOMContentLoaded の完了を待つ書き方が必要。今は body 末尾でOK

標準課題 std3-1：for文で N 個のスフィアを出す

土台HTML（★の部分だけ空欄）

HTML
<!DOCTYPE html>
<html>
  <head>
    <script src="https://aframe.io/releases/1.7.1/aframe.min.js"></script>
  </head>

    <a-scene>

      const group = document.querySelector('#group');   // 図形を入れる場所
      const N = 10;                                   // 出す個数（const=変えない値）

組み立てチャレンジ

  • 空欄1：N 回くりかえすための条件。for の真ん中は「いつまで続けるか」。i と N をどう比べる？
  • 空欄2：スフィアの色。文字列（クォートで囲む）で指定する。色名でも # 始まりの16進でもOK（自由に選ぶ）
  • できたら N を 5 や 20 に変えて、個数が変わることを確認する
つまったら：完成コード（scriptの中だけ）を見る 
JavaScript
const group = document.querySelector('#group');
const N = 10;
for (let i = 0; i < N; i++) {
  const ball = document.createElement('a-sphere');
  ball.setAttribute('position', `${i - 4.5} 1.5 -5`);
  ball.setAttribute('radius', 0.4);
  ball.setAttribute('color', 'gold');
  group.appendChild(ball);
}

空欄1＝N、空欄2＝'gold'。i - 4.5 で中央そろえ（i=0→-4.5, i=9→4.5）。金色の球が10個ならぶ。

座標リストを読み込んで、1つのスフィアを動かす

アニメーションの正体＝「位置を少しずつ変える」

CSVを読む関数と「async / await」

std3-4のコードには async function loadCSV(...) と await が出てくる。少し新しい書き方なので、ここだけ説明する（意味が分かればOK。まずは丸ごとコピーして使ってよい）。

  • なぜ必要？ fetch（ファイルを読む）は「時間がかかる処理」。押した瞬間には終わらず、データが届くまで少し待つ必要がある
  • await＝「この処理が終わるまで待ってから次に進む」という命令。待って、届いたデータを受け取る
  • await は async を付けた関数の中でしか使えない約束。だから loadCSV の頭に async を付ける
カップ麺と同じ。お湯を注いだら3分「待つ（＝await）」→ できてから食べる。await せずにまだできていないのに食べようとすると、中身が空っぽで失敗する（＝データが届く前に使おうとしてエラー）。

CSVを読む関数の全体（むずかしい書き方は使わず、for 文と if だけで書く）

やることはたった2段階。①ファイルを文字として受け取る（ここだけ await）→ ②その文字を for 文で1行ずつ「データの箱」に詰めかえる。②は第1回・第2回で習った for と同じ。

JavaScript
async function loadCSV(url) {              // ← awaitを使うので async を付ける
  const res  = await fetch(url);           // ① ファイルを取りに行く（届くまで待つ）
  const text = await res.text();           // ② 中身を1つの長い文字にして受け取る（受け取るまで待つ）

  const lines = text.trim().split('\n');   // ③ 改行(\n)で「1行ずつ」に分ける
  const rows = [];                          // ④ 詰めかえ先の空っぽの配列
  for (let i = 1; i < lines.length; i++) {   // i=1 から：1行目(見出し frame,team,…)は飛ばす
    const c = lines[i].split(',');         // カンマで5つの値に分ける → c[0]…c[4]
    const row = {                           // 5つの値を「名前つきの箱」にまとめる
      frame: Number(c[0]),                    // Number(...) は「文字→数値」に直す（"0"→0）
      team:  c[1],                            // team は文字のまま（'home'など）
      id:    Number(c[2]),
      x:     Number(c[3]),
      y:     Number(c[4])
    };
    rows.push(row);                        // 配列のうしろに1件ずつ足していく
  }
  return rows;                             // ⑤ 「行データの箱」を集めた配列を返す
}

  • split('\n')＝改行で切る→行の配列。split(',')＝カンマで切る→列（値）の配列。文字を切り分ける命令
  • Number('19.3')＝文字を数値に直す。CSVから読むと最初は全部「文字」なので、計算に使う x・y は数値へ直す
  • rows.push(row)＝配列のうしろに1件足す。for で124,200回くりかえすと、全データが rows にそろう
  • .then(function (rows) { ... })＝「読み終わったら、この中を実行して」。時間がかかる loadCSV の結果は、ここで受け取る（await と同じ「待つ」仲間）

CSVを反映して、23個をアニメーションさせる

やることは std3-2 とまったく同じ ── 点が23個に増えるだけ

  • 準備：23個の球を1回だけ作る（毎コマ作り直さない）。team-id をキーにして覚えておく
  • 再生：setInterval でコマ番号 f を1つずつ進め、そのコマの23件の位置を書きかえる
  • コマごとにデータを分けておくと速い（byFrame[f] ＝ f コマ目の23件）

標準課題 std3-5：全コマを再生してアニメーションにする

  // (A) コマごとにデータを仕分ける： byFrame[f] = そのコマの23件
  const byFrame = {};
  let maxFrame = 0;                          // 最後のコマ番号(=5399)も同時に探す
  for (let i = 0; i < rows.length; i++) {
    const r = rows[i];
    if (!byFrame[r.frame]) { byFrame[r.frame] = []; }  // そのコマの入れ物がまだ無ければ作る
    byFrame[r.frame].push(r);               // 同じコマ番号の所にためる
    if (r.frame > maxFrame) { maxFrame = r.frame; }
  }

  let f = 0;

      const r = now[i];
      const el = ents[r.team + '-' + r.id];
      place(el, r.x, r.y);            // このコマの位置へ移動
    }
    f = ____;                          // ★空欄1: 次のコマへ。最後まで行ったら0に戻す★
  }, ____);                            // ★空欄2: 間隔ミリ秒（例 100）★

3Dモデル（glTF / glb）を Sketchfab から入手して配置する

プリミティブの次は「本格的な3Dモデル」

  • これまでは球や箱（プリミティブ）だったが、A-Frameは他の人が作った精巧な3Dモデルも読み込める
  • glTF / glb は3Dモデルの標準フォーマット（“3DのJPEG”とも呼ばれる）。.gltf（テキスト＋画像の複数ファイル）と .glb（すべてを1つにまとめたファイル）がある
  • A-Frameは両方読めるが、.glb（1ファイル）が扱いやすいのでおすすめ
  • 例えばサッカーボールの3Dモデルを置けば、std3-5の白い球を本物のボールに置きかえられる

Sketchfab でモデルを入手する手順

Sketchfab は3Dモデルの共有サイト。無料でダウンロードできるモデルも多い。

  1. sketchfab.com を開き、キーワード検索（例：soccer ball）
  2. 左の絞り込みで Downloadable（ダウンロード可）にチェック
  3. モデルのページで ライセンスを確認（多くは表示義務のある CC）。利用条件を守る
  4. Download 3D Model ボタン → glTF 形式を選んでダウンロード（.glb か .zip）
  5. .zip のときは解凍し、中の .glb ファイルを使う
  6. その .glb を、index.html と同じフォルダに置く（例：model.glb）

ライセンスに注意

ダウンロードしたモデルには作者と利用条件（ライセンス）がある。授業の課題で使う範囲にとどめ、作者名の表示（クレジット）が必要なものは Notion に明記する。再配布・商用は条件をよく確認。
