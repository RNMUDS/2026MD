1

なぜ「サーバ」が要るのか ― HTTP と リアルタイム通信

これまでとの違い：1台で完結 → 複数をつなぐ

第3回まではブラウザ1台の中だけで動いていた（python -m http.server はファイルを配るだけ）。でも「お互いのアバターが見える」には、誰かの動きを別の人に届ける中継役が要る。それがサーバ。

HTTP は「手紙」。ほしいページを1回リクエストして、返事が来たら終わり（つなぎっぱなしではない）。一方リアルタイム通信は「通話」。回線をつないだままにして、どちらからでも好きなときに話しかけられる。マルチプレイには「通話」が向いている。
HTTP（これまで）リアルタイム通信（今回）
たとえ手紙（1往復で終わり）通話（つなぎっぱなし）
きっかけブラウザが要求したときだけどちら側からでも、いつでも
用途ページや画像を取りにいく位置の同期・チャット・通知

今日の道具：Node.js・Express・Socket.IO

  • Node.js：ブラウザの外で JavaScript を動かすしくみ。これで「サーバ側のJavaScript」が書ける
  • Express：index.html などのファイルをブラウザに配る、軽量な土台
  • Socket.IO：ブラウザとサーバを通話状態でつなぎ、メッセージを送り合うためのライブラリ

通信の基本形：emit（送る）と on（受け取る）

Socket.IO の通信は、たった2つの命令のペアでできている。片方が emit で送り、もう片方が同じ名前の on で受け取る。

考え方// 送る側
socket.emit('move', { x: 1, z: 2 });   // 'move' という名札をつけてデータを送る

// 受け取る側（別のプログラム）
socket.on('move', (data) => {      // 同じ名札 'move' が届いたら…
  console.log(data.x, data.z);        // 中身を使う
});
命令意味
socket.emit('名前', データ)その相手だけに送る
io.emit('名前', データ)自分も含めた全員に送る
socket.broadcast.emit('名前', データ)自分以外の全員に送る（アバター同期はこれ）
socket.on('名前', (データ) => {…})その名前が届いたら処理する（受信）

なぜ「自分以外の全員」に送るのか

自分の動きを自分に送り返す必要はない（自分のカメラはもう自分で動かしている）。だからアバター同期では socket.broadcast.emit を使って他の人にだけ「私はここに動いたよ」と伝える。

4

マルチプレイの仕組み ― 送る → 転送 → 受け取る

3ステップで「相手が見える」ようになる

お互いのアバターが見えるまでの流れは、次の3ステップだけ。std4-2 で①、std4-3 で②③を作る。

#どこですること
①自分のブラウザsetInterval で 100ミリ秒ごとに、自分の位置・向きを socket.emit('move', …) で送る
②サーバsocket.on('move') で受け取り、socket.broadcast.emit('moved', …) で自分以外の全員へ転送する
③相手のブラウザsocket.on('moved') で受け取り、送り主のアバターを作る／位置を更新する

なぜ100ミリ秒ごとに「間引く」のか

位置は毎フレーム（毎秒60回）変わるが、全部送るとサーバに負荷がかかる。setInterval で100ミリ秒ごと（毎秒10回）に間引くと、なめらかさと通信量のバランスが取れる。この「送る間隔」も、次回どれくらい細かくデータを取るか（サンプリング）の話につながる。

自分の位置・向きを「送る」

追記1: public/index.html の <script> の中（console.log の下）

JavaScript ── index.html に追記// 100ミリ秒ごとに、自分の位置と向きをサーバへ送る
setInterval(() => {
  const pos = cam.object3D.position;                          // 自分の位置
  const rotY = THREE.MathUtils.radToDeg(cam.object3D.rotation.y); // 向き（左右）

6

相手のアバターを同期して完成（標準ゴール）

標準課題 std4-3：受け取ってアバターを作る（②③）

最後に index.html の <script> に、受け取る処理を足す。届いた moved の位置に、相手のアバター（四角柱の胴体＋スフィアの頭）を作る／動かす。①〜④を埋めれば完成。

JavaScript ── index.html に追記（setInterval の下）// 他ユーザのアバターを作る（四角柱の胴体＋スフィアの頭）
function createAvatar(id, color) {
  const avatar = document.createElement('a-entity');
  avatar.setAttribute('id', id);
  avatar.innerHTML =
    '<a-box height="1.2" width="0.6" depth="0.6" color="' + color + '" position="0 0.6 0"></a-box>' +
    '<a-sphere radius="0.35" color="' + color + '" position="0 1.5 0"></a-sphere>';
  scene.①(avatar);        // シーンに追加する
  return avatar;
}

// 他ユーザが動いたら、そのアバターを作る／位置を更新する
socket.on('moved', (data) => {
  let avatar = document.getElementById(data.id);
  if (!avatar) {
    avatar = createAvatar(data.id, data.color);   // 初めて見るIDなら作る
  }
  avatar.setAttribute('②', data.position);            // 位置を更新
  avatar.setAttribute('rotation', '0 ' + data.rotation.y + ' 0'); // 向きを更新
});

// 他ユーザが退出したら、そのアバターを消す
socket.on('③', (id) => {
  const avatar = document.getElementById(id);
  if (avatar) avatar.parentNode.④(avatar);   // 画面から取り除く
});

仕上げ: server.js に「退出」を伝える処理を足す

JavaScript ── server.js の io.on('connection', …) の中に追記// 退出したら、全員にそのIDを伝えてアバターを消してもらう
socket.on('disconnect', () => {
  console.log('切断しました:', socket.id);
  io.emit('userLeft', socket.id);   // 全員に伝える
});

胴体 a-box の height／width や、頭 a-sphere の radius を変える。帽子（小さな a-cone）を足すのもよい。

アイデア③：Sketchfab の3Dモデル（glTF/glb）をアバターにする

第3回で学んだ <a-gltf-model> を使い、四角柱＋スフィアの代わりに好きな3Dモデルをアバターにする。Sketchfab でロボット・動物・キャラクターなどの glb をダウンロードして public に置き、createAvatar の innerHTML を差しかえる。（ライセンス・作者表示に注意）

JavaScript ── createAvatar の innerHTML を差しかえavatar.innerHTML =
  '<a-gltf-model src="robot.glb" scale="1 1 1"></a-gltf-model>';

アイデア④：VRM（3Dキャラクター）をアバターにする

VRM は「人型3Dアバター」の標準フォーマット。VRoid Hub や、無料アプリ VRoid Studio で作った自分のキャラを .vrm で置ける。A-Frame では aframe-vrm コンポーネントを読み込むと vrm 属性で表示できる。

HTML ── <head> に1行足す（VRMを使うとき）<script src="https://cdn.jsdelivr.net/npm/@binzume/aframe-vrm/dist/aframe-vrm.min.js"></script>
JavaScript ── createAvatar の innerHTML を差しかえavatar.innerHTML =
  '<a-entity vrm="src:avatar.vrm" rotation="0 180 0"></a-entity>';

※ .vrm ファイルは public に置く。向きが逆なら rotation="0 180 0" で調整する。

B. 空間そのものを作り込む

アイデア⑤：Sketchfab の建物・構造物を配置してワールドを作る

目印の白い箱を、本物の建物・家具・街灯・木・アーチなどに置きかえると、一気に「行きたくなる場所」になる。Sketchfab で building／street／cafe／park などを検索して glb をダウンロードし、public に置いて <a-scene> の中に並べる。

HTML ── a-scene の中に建物・構造物を並べる<!-- ダウンロードした glb を配置（位置・大きさ・向きは自由に調整） -->
<a-gltf-model src="building.glb" position="-8 0 -10" scale="2 2 2"></a-gltf-model>
<a-gltf-model src="streetlamp.glb" position="3 0 -4"></a-gltf-model>
<a-gltf-model src="tree.glb" position="6 0 -8" scale="1.5 1.5 1.5"></a-gltf-model>

さらに <a-sky> の色を夕焼けや夜空にしたり、a-light（ライト）を足したりすると雰囲気が出る。「どんな世界に友達を招きたいか」を考えて作り込もう。

3Dモデルを使うときの注意

  • ライセンス・作者表示を必ず確認する。授業の課題で使う範囲にとどめ、作者名（クレジット）が必要なものは Notion に明記する
  • モデルは node server.js ＋ http://localhost:3000 で開かないと読み込めない（file:// では動かない）
  • 重い（ポリゴン数の多い）モデルを大量に置くと動作が重くなる。まず1〜2個から試す
