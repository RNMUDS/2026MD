💡 良いテーマとは ― 「ゲームが面白い」ではなく「分析すると面白い」

評価されるのはゲームの完成度ではない。人の行動がデータとして見えるかどうかである。次のような問いが立つテーマを考えよう。

人はどこで立ち止まるのか 誰と誰がよく近くにいるのか 会話はどこで発生するのか 初心者と経験者で行動は違うのか 時間とともに行動はどう変化するのか グループ行動はどう形成されるのか リーダーは自然に現れるのか 空間デザインを変えると行動は変わるのか
「宝探しゲーム」を作るとき、ゲームとして考えると「宝をどこに隠すか」が問題になる。データとして考えると「人によって探索ルートは違うのか」「最短で見つける人には特徴があるのか」が問題になる。後者で企画すると、記録すべきものが自然に決まる（＝全員の移動軌跡と、発見までの時間）。

手順③ npm init -y ── このフォルダを「Node.js のプロジェクト」にする

Terminalnpm init -y

実行すると package.json という小さなファイルが1つできる。これはこのプロジェクトの説明書で、「名前は何か」「どんな部品を使っているか」が書かれる。-y は「名前は？ 作者は？ …」という質問を全部スキップして初期値でOKという意味。

package.json は料理のレシピ。材料（部品）の名前と分量（バージョン）が書いてある。レシピさえ渡せば、相手は同じ材料を自分でそろえられる ── だから提出時に node_modules（材料そのもの）を渡す必要はない。

ヒント① ― DB保存機能つきの、シンプルなマルチプレイ空間

これは何をするプログラムか

3つのヒントの土台になる作品。第4回（マルチプレイ）と第5回（ログ保存）を合体させたもので、次の3つを同時にやる。

  • みんなが同じ空間に入れる ─ 入室した人には色つきのアバター（頭＋体）が付き、他の人の画面にも現れる
  • 位置と向きが同期する ─ 0.1秒ごとに自分の position と rotation をサーバへ送り、全員に配る
  • その全部が記録される ─ 送られてきた位置をサーバが配列にため、退出したときに player_logs.db へまとめて書き込む

記録される表（player_logs）

1行が「ある人が、ある瞬間に、どこに居て、どこを向いていたか」。これが積み重なると、第3回で見たサッカーの位置データとまったく同じ形になる。

列意味分析でどう使うか
player_id誰か（匿名ID）人ごとにグループ分けする（groupby）
colorその人の色グラフで人を色分けする
timeいつ（ISO形式の文字列）滞在時間・時間帯ごとの変化
x / y / zどこに居たか移動距離・軌跡・よくいた場所のヒートマップ
rx / ry / rzどこを向いていたかry でどちらを向いていたか（見ていた方角）

なぜ「退出したときにまとめて」保存するのか

位置は1人あたり1秒に10件も届く。届くたびにデータベースへ書き込むと、人数が増えたときに重くなる。そこでメモリ上の配列 player.logs にためておき、退出時に一気に書き込む。
その代わりの注意点：サーバを Ctrl+C で強制終了すると、まだ書き込んでいない分は消える。データを取るときは必ず全員がブラウザを閉じてからサーバを止めること。

JavaScript ── server.js// ExpressでWebサーバを立てる
// Socket.IOでリアルタイム通信を行う

const express = require("express");
const http = require("http");
const { Server } = require("socket.io");
const sqlite3 = require("sqlite3").verbose();

const app = express();
const server = http.createServer(app);
const io = new Server(server);

// publicフォルダを公開する
app.use(express.static("public"));


// ========================================
// SQLite
// ========================================

// データベースを開く
const db = new sqlite3.Database("player_logs.db");

// テーブルを作る
db.run(`
CREATE TABLE IF NOT EXISTS player_logs(

    id INTEGER PRIMARY KEY AUTOINCREMENT,

    player_id TEXT,
    color TEXT,

    time TEXT,

    x REAL,
    y REAL,
    z REAL,

    rx REAL,
    ry REAL,
    rz REAL

)
`);


// ========================================
// プレイヤー情報
// ========================================

const players = {};


// ランダムな色を作る
function createRandomColor() {

    return "#" +
        Math.floor(Math.random() * 16777215)
        .toString(16)
        .padStart(6, "0");

}


// ========================================
// クライアントが接続した
// ========================================

io.on("connection", (socket) => {

    console.log("接続 :", socket.id);

    // プレイヤーを作る
    players[socket.id] = {

        id: socket.id,

        color: createRandomColor(),

        position: {
            x: 0,
            y: 1.6,
            z: 0
        },

        rotation: {
            x: 0,
            y: 0,
            z: 0
        },

        // 移動履歴を保存する配列
        logs: []

    };


    // 自分へ送る
    socket.emit(
        "自分の情報",
        players[socket.id]
    );


    // 現在いるプレイヤー一覧
    socket.emit(
        "プレイヤー一覧",
        Object.values(players)
    );


    // 他の人へ通知
    socket.broadcast.emit(
        "他者が入室した",
        players[socket.id]
    );


    // ====================================
    // プレイヤーが移動した
    // ====================================

    socket.on("自分が移動した", (data) => {

        const player = players[socket.id];

        if (!player) return;

        // 最新の位置
        player.position = data.position;

        // 最新の向き
        player.rotation = data.rotation;

        // 配列へ追加する
        player.logs.push({

            time: new Date().toISOString(),

            x: player.position.x,
            y: player.position.y,
            z: player.position.z,

            rx: player.rotation.x,
            ry: player.rotation.y,
            rz: player.rotation.z

        });

        // 他のプレイヤーへ送る
        socket.broadcast.emit(
            "他者が移動した",
            player
        );

    });


    // ====================================
    // プレイヤーが退出した
    // ====================================

    socket.on("disconnect", () => {

        console.log("切断 :", socket.id);

        const player = players[socket.id];

        if (player) {

            // SQLiteへまとめて保存
            player.logs.forEach(log => {

                db.run(

                    `INSERT INTO player_logs
                    (
                        player_id,
                        color,
                        time,
                        x,
                        y,
                        z,
                        rx,
                        ry,
                        rz
                    )
                    VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?)`,

                    [

                        player.id,

                        player.color,

                        log.time,

                        log.x,
                        log.y,
                        log.z,

                        log.rx,
                        log.ry,
                        log.rz

                    ]

                );

            });

        }

        // メモリから削除
        delete players[socket.id];

        // 他のプレイヤーへ通知
        io.emit(
            "他者がいなくなった",
            socket.id
        );

    });

});

ヒント② ― 「見たデータ」も記録する空間（注視の検出と注視時間）

何を足すのか：画面の中心の円と重なったオブジェクトを検出する

ヒント①では「どこに居たか」しか分からなかった。ここでは「何を見ていたか」を足す。画面のまん中に小さな円（カーソル）を出し、その円がオブジェクトと重なっている間の時間をはかって記録する。

美術館で、あなたが今どの絵の前に立っているかは「位置」で分かる。でも本当に見ていたかは分からない ── 隣の絵を見ながら立っているかもしれない。視線の先にあるものを測るのが、この仕組み。VRの世界では「ゲイズ（gaze）」と呼ばれ、実際の視線計測の代わりによく使われる。
  • A-Frame の <a-cursor> をカメラの中に置くと、画面の中心から前方へ見えない光線（レイ）が伸びる
  • その光線がオブジェクトに当たると mouseenter、外れると mouseleave というイベントが発生する
  • だから 「当たった時刻」を覚えておいて、「外れた時刻」との差を取るだけで注視時間になる

足すコード①：見られる対象に目印をつける（HTML）

見られたいオブジェクトに class="lookable"（＝光線の当たる相手）と data-name="…"（＝記録に残す名前）を付ける。この2つが目印になる。

HTML ── 見られる対象<!-- class と data-name が目印。data-name がそのまま記録に残る -->
<a-box class="lookable" data-name="作品A"
       position="-4 1.5 -6" width="2" height="2" depth="0.2"
       color="#E74C3C"></a-box>

そしてカメラの中に円のカーソルを入れる。raycaster="objects: .lookable" と書くことで、lookable が付いたものだけを判定の対象にできる（床や空に反応させない）。

書いたもの意味
<a-cursor>画面の中心に出る円。カメラの子にすると、いつも視線の正面に来る
fuse="false"「一定時間見つめたら自動クリック」を切る（今回は見た時間だけ測りたいので不要）
objects: .lookable判定する相手を絞る。これが無いと床や空にも当たってしまう
far: 30光線の届く距離（メートル）。遠すぎる物まで「見た」ことにしたくないときは小さくする

足すコード②：時間をはかる（JavaScript）

やることは 「入ったら時刻を覚える／出たら差を取って送る」だけ。

JavaScript ── public/index.html の中const cursor = document.querySelector('a-cursor');

// いま見ているオブジェクトと、見はじめた時刻
let gazeTarget = null;
let gazeStart = null;

// 短すぎる注視（通りすがり）は記録しない
const MIN_GAZE_MS = 300;

// 円がオブジェクトに重なった
cursor.addEventListener('mouseenter', (event) => {
    const target = event.detail.intersectedEl;
    if (!target) return;

    gazeTarget = target;
    gazeStart = new Date();

    // 見られている間だけ、少し薄くする（自分への合図）
    target.setAttribute('opacity', 0.5);
});

// 円がオブジェクトから外れた
cursor.addEventListener('mouseleave', () => {
    if (!gazeTarget) return;

    const gazeEnd = new Date();
    const duration = gazeEnd - gazeStart;   // ミリ秒

    gazeTarget.setAttribute('opacity', 1);

    if (duration >= MIN_GAZE_MS) {
        socket.emit('見た', {
            object_name: gazeTarget.dataset.name,
            start_time: gazeStart.toISOString(),
            end_time: gazeEnd.toISOString(),
            duration_ms: duration
        });
    }

    gazeTarget = null;
    gazeStart = null;
});

  • 短い注視を捨てている（MIN_GAZE_MS = 300）。首を振っている途中に一瞬かすっただけのものを「見た」と数えると、データがノイズだらけになる。このしきい値をいくつにするかは、あなたの分析の重要な判断であり、レポートに書くべきこと
  • ページを閉じる直前（beforeunload）にも送っている。見ている途中で退出した分を捨てないため
  • これは本当の視線ではなく「画面の中心に何があったか」。この違いは考察で正直に書くとよい

ヒント③ ― 「行動データ」も記録する空間（ボタン・クリック・接近）

何を足すのか：起きたことを、なんでも1つの表に入れる

ヒント①は「どこに居たか」、ヒント②は「何を見たか」。ここでは「何をしたか」を記録する。しかも種類が増えても表を増やさない作り方をする。

  • アクションボタンを押した ─ 画面下のボタン、またはキーボード（E / R）
  • オブジェクトをクリックした ─ 画面中心の円を合わせてクリック
  • 誰かに近づいた／離れた ─ サーバが0.5秒ごとに全員の距離を測って自動で記録（一緒にいた時間つき）
  • おまけで 入室・退室も記録する（滞在時間の計算に使える）

表の設計：event_logs ひとつで全部まかなう

行動の種類ごとに表を作ると、新しい行動を思いつくたびに表が増えて分析が大変になる。そこで「何が起きたか」を列の値で表す。実務のイベントログでも定番の設計。

SQL ── event_logsCREATE TABLE IF NOT EXISTS event_logs(
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    player_id TEXT,
    time TEXT,
    event_type TEXT,   -- 何が起きたか（"手をふる" "接近" "クリック" …）
    target TEXT,       -- 相手・対象（相手のID、押したオブジェクト名 …）
    x REAL, y REAL, z REAL,

event_typetargetvalueいつ記録されるか

クリック押したオブジェクト名0円を合わせてクリックしたとき
接近相手の player_idそのときの距離（m）2人の距離が3m未満になった瞬間
離脱相手の player_id一緒にいた時間（ミリ秒）2人の距離が3m以上に離れた瞬間

value の意味は event_type によって変わる

上の表のとおり、接近 のときは距離、離脱 のときは時間が入る。1つの列を使い回すのは便利だが、意味を表にして書き残さないと、後で自分でも分からなくなる。レポートの「取得データ」の項目に、必ずこの対応表を書くこと。

ここに詰まっている3つの工夫（作るとき必ず必要になる）

  • 「状態が変わった瞬間」だけ記録する。0.5秒ごとに「近い」を記録すると、10秒一緒にいただけで20行たまる。接近した瞬間と離れた瞬間の2行にすれば、そのあいだの時間もきれいに出る
  • ペアの名前をそろえる。[a.id, b.id].sort().join("+") としないと、A+B と B+A が別のペアとして数えられてしまう
  • まだ動いていない人を除く（ready）。全員の初期位置は原点なので、そのままだと入室した全員が必ず「接近」と記録される。クライアント側でも開始位置をばらけさせて、この偽の接近を防いでいる
